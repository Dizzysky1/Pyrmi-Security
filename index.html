Anti-cheat for web games.
One script tag.

Pyrmi spots bots, speed hacks and faked scores in the browser. Your server asks for a verdict before it saves a score, and the dashboard shows every flag and why.

// how it works

1

Add the script

Each run gets a signed session from a real page load. The script watches for automation, scripted input, replaced browser functions and clock tricks.

2

Check on your server

Before saving a score, call pyrmi.verify(). You get accept, review or reject, a risk score from 0 to 100, and the reasons.

3

Watch it work

The dashboard shows every verdict, which checks fired, and which players keep getting flagged. Tune the limits as you learn your game.

in your game page 
<script src="https://pyrmi.com/sdk/pyrmi.js" data-site="pk_..."></script>
<script>
  // when a run starts
  const run = await Pyrmi.start();
  // when it ends: send run.token with the score
  await Pyrmi.flush();
  await fetch('/scores', { method: 'POST',
    body: JSON.stringify({ token: run.token, score }) });
</script>
on your server 
const { Pyrmi } = require('pyrmi-server');
const pyrmi = new Pyrmi({ secretKey: process.env.PYRMI_SECRET_KEY });

const v = await pyrmi.verify({ token, score, player });
if (v.verdict !== 'reject') saveScore(player, score);

// what it catches

Edited scoresDeterministic games replay the recorded inputs on the server. A memory hack or a typed-in score won't reproduce.
Direct API callsNo signed session from a real page, or a session that never sent telemetry, and the score is flagged.
Replayed submissionsEach session token works once and expires. Sending the same winning request twice fails.
Bots and headless browsersWebdriver flags, headless Chrome, Playwright, Puppeteer, Selenium and Cypress markers.
Speed and slow-mo hacksThe page clock and your game clock are checked against the server's real time.
Impossible runsRuns longer than the session existed, scores past your caps, or scores that grow too fast.
Scripted inputSynthetic events and key timing that's too even or too fast for a human hand.
Tampered runtimeReplaced performance.now, requestAnimationFrame, fetch and other built-ins.
What it won't doBlock devtools or "stop code running". Whoever owns the browser can switch any of that off. Pyrmi watches and reports, and your server has the final say.
